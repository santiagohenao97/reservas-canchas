# E3 · Contenedor, configuración y entorno reproducible

**Objetivo:** una primera ejecución que otra persona pueda repetir.
**Rama:** `ejercicio-3-contenedor` · **Requiere:** Docker con Compose. Nada de nubes.

## Qué agrega esta etapa
| Pieza | Qué resuelve |
|---|---|
| `Dockerfile` | La imagen: usuario sin privilegios, `HEALTHCHECK`, versión y revisión como etiquetas |
| `compose.yaml` | Cómo se ejecuta: puerto y configuración por entorno, datos en un volumen |
| `.env.example` → `.env` | Configuración fuera de la imagen. `.env` no se versiona |
| Una reserva real | La prueba de verdad: crear y listar una reserva, no solo "responde" |
| `comprobar.sh` · `./dev` (opcional, bash) | Lo mismo hecho script: lo repetible, automatizado |

## Pruébalo
Sigue los pasos 1 a 7 de "Lo mínimo para verlo funcionando" en el `README.md`. Funcionan en Mac, Linux y Windows (PowerShell). Además, revisa que la imagen se puede identificar:
```
docker image inspect reservas-canchas:local --format '{{json .Config.Labels}}'
```
Debe mostrar el título, la versión y la revisión.

## Rómpelo (ejercicio)
1. Cambia `PORT` en `.env` y vuelve a levantar con `docker compose up -d --build`. ¿Qué tuviste que cambiar en tus comandos y direcciones? ¿Y en la imagen?
2. Crea una reserva, haz `docker compose down` y vuelve a levantar: ¿sigue la reserva? ¿Y después de `docker compose down -v`?
3. Agrega la línea `FALLA=db` al final de `.env` y vuelve a levantar: falla a propósito. Antes de mirar el código, diagnostica con `docker compose ps`, http://localhost:8000/salud y `docker compose logs`. Al terminar, borra esa línea y vuelve a levantar.
4. Pide a un compañero que arranque tu servicio **solo con tu README**. Anota dónde se atascó.

Opcional (bash: Mac, Linux, Git Bash o WSL): `./dev levantar` hace lo mismo en un paso y `./dev diagnosticar` arma la evidencia para pedirle un diagnóstico a una IA. Compáralo con tu propio diagnóstico del punto 3.

## Estado real de esta etapa
- **ejecutado:** imagen construida, contenedor arriba, reserva real creada y listada, datos persistentes.
- **comprobado con una muestra:** el `HEALTHCHECK` (una sola máquina, una sola versión de Docker).
- **solo diseñado:** cualquier ejecución fuera de tu equipo.
